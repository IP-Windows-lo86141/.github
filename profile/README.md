<p>Windows 的配置路径比手机多，也更容易互相覆盖：系统代理、浏览器代理、客户端接管，三层都能改出口。这篇按先系统后浏览器的顺序讲，给出每一步的验证方式，最后是三类常见冲突的处理。</p>
<h2>一、先选配置层级</h2>
<p>层级一，系统代理：设置里填地址与端口，影响大多数应用。层级二，浏览器代理：只影响浏览器，隔离性好。层级三，客户端接管：全局或分流，覆盖最广。</p>
<p>多账号运营建议用层级二或三，单账号用层级一即可。三层同时开容易互相覆盖，改完不知道哪层生效。</p>

<thead><tr><th>层级</th><th>影响范围</th><th>适合</th></tr></thead>
<tbody>
<tr><td>系统代理</td><td>多数应用</td><td>单账号</td></tr>
<tr><td>浏览器代理</td><td>单个浏览器</td><td>多环境</td></tr>
<tr><td>客户端</td><td>全局或分流</td><td>复杂场景</td></tr>
</tbody>
</table>
<h2>二、配置步骤</h2>
<p>第一步，打开设置里的网络与代理，关闭自动检测，手动填地址与端口。第二步，保存后打开浏览器访问回显页，确认出口。</p>
<p>第三步，检查时区与语言是否与地址地区一致。第四步，重启浏览器，再验证一次，确认设置未被重置。两步验证都过，再登录账号。</p>
<h3>命令行的验证方式</h3>
<p>用命令行查出口更直接：请求一个回显接口，看返回的地址。也可以查本机路由表，确认流量确实走了代理。命令行结果不受浏览器缓存影响，更适合排查。</p>
<h2>三、三类冲突</h2>
<p>冲突一，客户端与系统代理同时开，流量绕两圈，速度慢且不稳定。冲突二，浏览器插件自带代理，覆盖了系统设置。冲突三，安全软件拦截代理端口。</p>
<p>处理方式统一：先关掉多余的一层，只留一个生效，再逐层加回。逐层加回能定位是哪一层在冲突。</p>

<h2>四、长期维护</h2>
<p>把配置导出备份，系统重装后直接恢复。客户端版本更新后重新验证出口，避免默认设置被改。环境命名与账号对应，避免混用。</p>
<p>每周记录一次出口，与台账核对。发现漂移，先查客户端日志，再查线路。</p>
<h2>五、配置完成后的三项记录</h2>

<h2>六、多环境下的配置管理</h2>
<p>一台电脑跑多个环境时，配置管理比配置本身更重要。每个环境一套代理设置，环境之间不能互相读取，否则隔离就失去意义。</p>
<p>管理方法很简单：环境命名带账号编号，配置文件放在对应目录，改动前先导出备份。三件事做完，换人接手也不会乱。</p>
<p>最容易出问题的是系统级设置被其他软件改动。安装新软件、更新系统、切换网络，都可能重置代理。养成登录前看一眼出口的习惯，比事后排查省事。</p>
<h2>常见问答</h2>
<h3>Windows 需要装客户端吗？</h3>
<p>答：不必须。系统代理够用，客户端在需要分流或全局时更方便。</p>
<h3>系统代理会影响所有软件吗？</h3>
<p>答：多数遵守系统设置的软件会，部分自带代理设置的不受影响。</p>
<h3>浏览器显示出口不对怎么办？</h3>
<p>答：先禁用插件，再检查是否开了浏览器自带代理，最后看系统设置。</p>
<h3>能同时配两个出口吗？</h3>
<p>答：能，用不同浏览器或虚拟机区分。同一环境配两个出口会互相覆盖。</p>
